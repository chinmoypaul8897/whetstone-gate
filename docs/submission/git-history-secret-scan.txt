1. METHOD — TWO SCANS, AND THE SECOND IS A SUPERSET OF THE PRESCRIBED ONE
--------------------------------------------------------------------------------

  1a. `PROCESS.md` §8's LITERAL PRESCRIBED FORM, run as written:

        git log -p --all | grep -nEi '<key patterns>'

      The frozen method is executed as specified rather than substituted for
      something the runner preferred.

  1b. AN ALL-OBJECTS SCAN, which is STRICTLY STRONGER:

        git cat-file --batch-all-objects --batch-check='%(objectname) %(objecttype)'
        git cat-file blob <oid>          # for every blob, reachable or not

      ⚠️ WHY THE STRONGER ONE WAS ALSO RUN. `git log -p --all` walks the DIFFS of
      commits REACHABLE FROM REFS. An object left behind by an abandoned commit, an
      interrupted rebase, or a discarded stash is invisible to it — and is still
      served by `git cat-file`, and still travels in a `--mirror` clone. On a
      repository about to be made public, "unreachable" is not "absent". The scan
      found exactly one such object (§3, `c15e9bfa`), which the prescribed form
      would not have reported as an object at all.

  1c. THE PATTERNS ARE IMPORTED, NEVER RETYPED.

      They come from `whetstone_gate.check_roles.SECRET_PATTERNS` at run time, so
      this scan and `check-roles` C1 cannot drift into two different answers about
      what a secret looks like. `REVIEW_C0.md` F-05 measured what that costs: a
      mutant that reduced the scanner to 1 of its 8 patterns SURVIVED the suite.

  1d. ⚠️ NO MATCHED BYTE IS PRINTED ANYWHERE IN THIS FILE. `CLAUDE.md` §4: "Never

4. ⚠️ THE PROOF THAT IT IS NOT A CREDENTIAL — STATISTICS AND A DIGEST, NO BYTES
--------------------------------------------------------------------------------

  Structural characterisation of the matched string, computed and reported without
  the string reaching stdout:

      total length                        : 30
      payload length after the `gsk_`     : 26
      DISTINCT characters in the payload  : 26      <- every character appears ONCE
      lowercase only                      : yes
      strictly alphabetic                 : no      <- so it contains digits too

  ⚠️ 26 CHARACTERS OF WHICH 26 ARE DISTINCT IS NOT WHAT ENTROPY LOOKS LIKE. A
  provider-issued Groq key is ~52 base62 characters with the repetition you would
  expect from a random draw. A 26-character string with no character repeated even
  once is an enumeration, not a secret.

  THE CONSTRUCTION, CONFIRMED BY DIGEST RATHER THAN BY INSPECTION:

      sha256("gsk_" + "0123456789" + "abcdefghijklmnop")[:16] = c0d5ddd6993f0732
      sha256(<the matched bytes>)[:16]                        = c0d5ddd6993f0732
                                                          IDENTICAL.

  ⚠️ THE STRING IS THE DIGITS 0-9 FOLLOWED BY THE FIRST SIXTEEN LETTERS OF THE
  ALPHABET, BEHIND A `gsk_` PREFIX. Naming that construction is safe precisely
  because it is manifestly not a credential; the bytes themselves are still not
  written here, and the digest is what carries the proof.

  ⚠️ AND ITS NEIGHBOUR IN THE SAME FIXTURE TUPLE IS THE SAME IDEA IN GOOGLE'S SHAPE:
  `AIzaSyD0123456789abcdefghijklmnop` — 33 characters, which is SHORT of the Google
  pattern's required 39, so it did not fire at all. Two placeholders written the
  same way by the same hand, one of which happened to be long enough to trip the
  scanner and one of which was not.

  ⚠️ THE ONE THING THIS DOES NOT PROVE, STATED RATHER THAN GLOSSED. It proves the
  four hits are a placeholder. It does not prove no secret ever entered this history
  in a shape none of the eight patterns describes — an unprefixed token, a
  base64 blob, a password. No pattern scan can prove that, and this file does not
  claim it. What the project has against that residue is `runner/redaction.py`, the
  `.gitignore`, `check-roles` B1/C1, and the fact that no payment method is attached
  to either provider account.
